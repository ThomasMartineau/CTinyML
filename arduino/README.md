# Arduino test sketch

`ctinyml_serial_infer/` is a self-contained sketch for the Arduino Mega 2560. It wraps the compiled
`model_forward()` with a small serial protocol so `tools/serial_infer.py` can stream real MNIST
digits to the board and read back predictions.

## Flash it

1. Open `arduino/ctinyml_serial_infer/ctinyml_serial_infer.ino` in the Arduino IDE.
2. Select **Tools > Board > Arduino Mega or Mega 2560** and your COM port.
3. Click **Upload**.
4. Run the host harness (close the Serial Monitor first, it holds the port):

```bash
uv run --extra dev python tools/serial_infer.py --port COM5 --n 50
```

## Contents

| File | Origin |
|---|---|
| `ctinyml_serial_infer.ino` | Hand-written serial harness |
| `model.c` | Generated by `ctinyml compile` (weights are baked in) |
| `pgm_read_f32.h`, `qmath.h`, `conv2d_direct.h`, `gemm.h`, `argmax.h` | Copied from `ctinyml/targets/avr/runtime/` |

The IDE compiles `model.c` automatically because it sits in the sketch folder, and its quoted
`#include`s resolve to the headers beside it.

## Serial protocol (115200 baud)

1. Board sends `READY\n` once after `setup()`.
2. Host sends one sync byte `0xAA`, then 784 pre-quantized int8 pixels (row-major).
3. Board replies with one byte: the predicted class (0-9).

The board does no quantization. The host quantizes with the model's input scale and zero point, so
`tools/serial_infer.py` must be built from the same model and calibration data as the flashed `model.c`.

## Regenerate `model.c` and the headers

From the repo root, compiling the MNIST fixture straight into the sketch folder:

```bash
uv run python -m ctinyml compile tests/fixtures/mnist/mnist_classifier.onnx --target avr \
    --calibration tests/fixtures/mnist_holdout.npz -o arduino/ctinyml_serial_infer
```

`tools/serial_infer.py` is hard-coded to that fixture, so flash a different model only if you also
update the script.
